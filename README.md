# 公众号文章下载与阅读 · wechat-article-reader

把公众号文章链接批量保存为 Markdown，并生成一张记录成功和失败的总表。只提取标题、正文和基本信息，不采集阅读数，不使用付费 API 或大模型。

也可以安装为 Codex skill：收到公众号链接后，先下载，再由当前助手完整阅读正文，进行总结、分析或对比。

## 快速开始

适用于 macOS / Linux，需要 Git 和 Python 3.9+（使用 OpenSSL，推荐 Python 3.12）。下载器首次运行时需要联网安装依赖。使用 skill 还需要能运行本地命令、读取文件的 Codex 环境。

```sh
git clone https://github.com/yuanl0116/wechat-article-reader.git
cd wechat-article-reader
sh install-skill.sh
```

随后在已加载该 skill 的 Codex 聊天中发送：

```text
用 $wechat-article-reader 读一下这篇文章：https://mp.weixin.qq.com/s/文章短码
```

请保留克隆的整个项目；skill 会使用其中的下载器。安装不会把下载器内嵌到普通网页版聊天中。无需另外申请 API Key。

## 作为阅读 skill 使用

项目附带 `wechat-article-reader`，让 Codex 在收到公众号链接后，先用本项目下载，再完整读取保存的正文，按要求总结、分析或对比。只发送链接时默认给出简短要点和本地文件链接；明确说“只下载”时只归档。下载器本身不调用大模型，阅读由当前聊天里的助手完成。

在项目目录执行一次安装：

```sh
sh install-skill.sh
```

安装器把项目内 `skills/wechat-article-reader` 通过软链接注册到 `${CODEX_HOME:-~/.codex}/skills/`，重复安装不会覆盖其他文件。请保留项目目录；项目移动后需更新该软链接。

在已加载该 skill 的聊天中，可以直接发公众号文章链接，也可以明确指定：

```text
用 $wechat-article-reader 读一下这篇文章：https://mp.weixin.qq.com/s/文章短码
```

每次任务使用独立的 `input/skill_<随机编号>.txt`，不覆盖原有链接文件。下载后先检查本批总表，再分块读完每篇可读正文。图片备份失败或元数据缺失时，仍读取已保存的文字并说明归档缺失；关键内容在图片里时需另外查看本地图片。验证、删除、网络失败等仍受原下载器限制，无法取得正文时不会声称已读。

## 怎么用

可以直接在聊天里把链接发给助手，请助手按原顺序保存到本项目的 `input/links.txt` 后运行。也可以自行编辑这个文件，一行一个链接，允许空行、重复链接和以 `#` 开头的备注。

```sh
cd wechat-article-reader
sh run.sh
```

首次使用会自动创建本项目的 `.venv` 并安装依赖；需要联网。使用 Python 3.9 或更新版本，推荐 Python 3.12，须使用 OpenSSL；脚本会优先查找较新的已安装 Python。

支持 `https://mp.weixin.qq.com/s/短码` 和 `https://mp.weixin.qq.com/s?__biz=...&mid=...&idx=...&sn=...`。会清理首尾空格、常见中文标点、`#rd` 和常见分享跟踪参数，不修改你给的原始链接记录。每一行只放一个链接。

也可以指定本项目内的其他文件和输出父目录：

```sh
sh run.sh --input input/other-links.txt --output output
sh run.sh --help
```

输入、输出及其软链接解析后的路径都必须在本项目目录内。

## 输出在哪

每次运行创建一个独立批次，例如 `output/20261116_235000/`，时间按北京时间，精确到秒；同秒运行也不会覆盖之前的批次。

```text
output/<批次名>/
  2026-11-16_公众号名_标题前20字.md
  2026-11-16_公众号名_标题前20字_images/
    001.png
    002.jpg
  _总表.csv
  _运行报告.json
  _输入链接.txt
  _原始网页/
    001.html
```

- Markdown 信息头包含：标题、公众号、作者、发布时间、原链接、抓取时间、正文字数、图片数。作者没有就留空；发布时间缺失时不会猜测日期。
- 文件名中的非法字符替换为 `_`。标题最多取原文前 20 字，公众号名最多 30 字；文件同名时追加 `_2`、`_3` 等。
- 保留小标题、段落、加粗、列表、引用、正文超链接及普通 HTML 表格。识别公众号常用的 `data-src` 懒加载图片。
- 每张图片前后各有一个相同编号的标记，例如 `【图1】`。编号按正文出现顺序连续递增；Markdown 始终使用原图地址，本地图片只作备份。原图链接失效后，可以根据编号找到本地备份。
- 同一图片在正文出现多次，分别按位置保存为多个编号文件；同一个图片地址只下载一次，复用已下载内容，因此成功文章的备份文件数与“图片数”一致。
- **正文字数**指正文中除空白以外的可见字符数，含标点及数字，不包含信息头、Markdown 语法、图号和图片替代文字。图片数指正文中有效图片标签的出现次数。
- `_总表.csv` 用带 BOM 的 UTF-8 编码，便于用 Excel 打开。列严格为：`序号,原链接,状态,标题,公众号,发布时间,正文字数,图片数,md文件名,失败原因`。
- 总表每个唯一链接一行；序号按去重后输入顺序递增。重复行及其首次出现的行号记录在 `_运行报告.json`，不会重复抓取或出文件。
- `_运行报告.json` 另含各状态数量、验证比例、是否提前停止、已清理的关注引导原文，以及逐图备份清单和错误原因。
- `_输入链接.txt` 保存本批原始输入副本；`_原始网页/` 保存本批实际收到的页面，供本地排查和对照正文，程序不会执行其中的脚本。网络连接失败、无效输入或提前停止时不会有对应网页快照。

不同短链和长链如果实际上指向同一文章，只有在能从输入本身确认相同时才去重：短链去掉跟踪参数后比较；长链以 `__biz + mid + idx` 为标识。不能在未访问页面前推断任意两个不同短码是否指向同一篇文章。

## 各状态是什么意思

| 状态 | 含义 |
| --- | --- |
| 成功 | 已提取标题、公众号、发布时间和文字正文，Markdown 已保存，所有正文图片均已备份。 |
| 文章已删除或违规 | 页面明确提示内容已删除、违规、投诉后无法查看等。跳过该文章。 |
| 需要验证 | 页面提示环境异常、安全验证、访问过频，或跳转到验证码页面等。不会绕过或自动重试。 |
| 不是图文文章 | 纯图片、视频号、转载卡片等页面没有能提取的文字。已知的图片/视频描述区有文字时仍会尝试保存。 |
| 其他失败 | 链接错误、网络超时、页面结构未知、关键信息缺失、图片备份不完整，或因提前停止而尚未请求。具体原因见总表。 |

图片下载失败或关键信息缺失时，仍尽量保存已有正文和成功下载的图片，但状态记为“其他失败”，避免将不完整的归档报为成功。失败图片会列明图号及原因，不会生成伪图片凑数。

## 访问节奏与验证页

文章请求之间随机等待 3–6 秒，顺序执行；不同图片下载之间另有短暂停顿。每个地址不做自动重试。

为避免首批测试遇到大量验证页仍继续访问，当至少请求 3 条文章且验证页占已请求文章的比例达到 50% 时，立即停止后续请求，打印比例。剩余链接仍进入总表，记为“其他失败”，原因写明“此链接未请求”。分母只计实际尝试请求的文章，不计本地校验失败和未请求项。是否换到其他机器由你决定。

终端会打印成功数、失败数、重复数、各类失败数量和输出目录。按 `Ctrl+C` 会保存当前总表，并把后续链接记为未请求。退出码：全部成功为 `0`；输入/环境等批次错误为 `1`；有任何文章失败或因验证提前停止为 `2`；用户中断为 `130`。

脚本只处理已收到页面中的正文，不运行页面 JavaScript，不绕过验证。清理页面关注二维码组件、底部操作栏、隐藏节点、脚本和样式；对短而独立的“点击上方关注”“扫码关注”“我是…喜欢我的文章请点关注”等引导也会清理，并在运行报告中记录原文。其他和文章内容混在一起的文字不会仅凭“关注”等关键词删除。极特殊的页面结构可能需要用保存的网页快照调整提取规则。

## 检查与测试

```sh
.venv/bin/python -m unittest discover -s tests -v
```

测试只在本项目 `tests/` 下临时读写，不请求微信；覆盖正文层级、图片位置与连续编号、备份数量、原链接信息头、作者缺失、日期转换、短长链清理和去重、错链接不中断、删除与验证分类、大量验证停止、图片失败不重试、不完整归档状态、文件重名和路径边界。测试使用人工编写的本地页面，不能代替真实文章验收。

真实文章验收时：查看本批 `_总表.csv`，挑一篇 Markdown 对照原文，检查段落、图片位置与图号，并核对其 `_images/` 内文件数和总表图片数一致。程序会保留实际收到的网页快照，以便不重复抓取即可检查提取结果。

## 项目范围

代码、虚拟环境、安装缓存、输入、输出、测试临时目录和 Git 仓库都位于你克隆的项目目录内。安装 skill 时会在个人 skills 目录额外创建一个指向项目的软链接。个人输入、文章输出、虚拟环境和缓存已加入 Git 忽略规则；公共仓库仅保存程序、skill、说明文档和人工编写的测试素材，不包含下载的公众号文章。
